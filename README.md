# VidiStudio for macOS

A native SwiftUI and AVKit video accessibility editor with a portable Python command-line engine. Requires macOS 26 or later. The app uses local project folders; there is no Firebase, Firestore, sign-in, or cloud storage dependency. The editor is native; a WebKit view embeds only the YouTube player for YouTube projects.

## Bring Your Own Key (BYOK) Architecture

VidiStudio is built on a **Bring Your Own Key (BYOK)** system. **A personal Google Gemini API key must be configured in Settings before utilizing this application to create projects or perform AI processing.**

### Why BYOK is a Key Feature:
- **Zero Subscriptions & Middlemen:** VidiStudio has no monthly platform fees, centralized server proxies, or account registrations. You connect directly from your Mac to Google's official Gemini API endpoints.
- **Direct Quota & Pricing Control:** Use your own [Google AI Studio](https://aistudio.google.com/) account. You can utilize the generous Free tier or pay-as-you-go pricing, paying Google directly with zero markups or token resale fees.
- **Hardware-Backed Credential Security:** Your Gemini API key is stored securely in the native **macOS Keychain** (`com.vidistudio.gemini-api`). It is never written to plaintext configuration files on disk, never committed to project folders, and never logged.
- **Prerequisite Enforcement:** Project creation (via File → New Project, `Command-N`, toolbar buttons, or the Finder/Safari Share extension) is strictly gated on having a valid Gemini API key configured. If no key is configured, VidiStudio immediately redirects to **Settings → Gemini API** so you can enter your key before proceeding. Automated speech transcription, scene summaries, Audio Description generation, cue rewriting, frame OCR ("Read Frame Text"), YouTube video accessibility validation, and Gemini TTS narration all use your configured BYOK key.

## Build and run

```sh
./script/build_and_run.sh --verify
```

This builds the existing `VidiStudio.xcodeproj` app target, freezes the Python engine and Google GenAI SDK with PyInstaller, bundles FFmpeg/FFprobe and their non-system libraries, signs the bundle with the local Apple Development certificate, and opens it. Xcode is selected per command using `DEVELOPER_DIR`, without changing global developer settings. Python build dependencies live in `.venv`. The script requires exactly one Apple Development signing identity in Keychain; if there are several, set `VIDISTUDIO_SIGNING_IDENTITY` to the desired certificate SHA-1 shown by `security find-identity -p codesigning -v`. It will stop rather than produce an ad hoc signed app that can lose macOS folder permissions after updates.

Other flags: `--build-only`, `--debug`, `--logs`, `--telemetry`. `script/package.sh` makes Release local-install ZIP and DMG packages in `dist`. Local signatures are not Developer ID notarization; public distribution requires signing and notarizing all nested code with the owner's distribution credentials.

For persistent Documents folder access, launch the same signed copy from `/Applications/VidiStudio.app` each time. Install a newly built app over that path rather than opening a build product from Xcode's DerivedData or this repository's `build/DerivedData`. After switching from an older ad hoc signed copy to a certificate-signed one, macOS may ask once more. Allow it under System Settings → Privacy & Security → Files & Folders if needed; future builds signed with the same certificate and bundle ID should retain the grant. Xcode's normal Run action signs with the development team configured in the project, but launches its own build location.

## Workflow

1. **Initial Setup — Bring Your Own Key (BYOK):** Open Settings (Command-comma) → **Gemini API** and save your Google Gemini API key and model names. You must configure this key before creating projects, as the File > New Project command, toolbar button, and Share extension are gated on having an API key configured. Use **Check API Key & Plan** to verify the key, automatically detect your Free or Paid plan, and populate the compatible model catalog.
2. **New Project (Command-N):** With your API key saved, choose a video file or YouTube video. Video files are copied into the project library and receive video details and eight timeline pictures. YouTube videos must be publicly available with visibility set to Public or Unlisted; Private and restricted visibility settings are rejected because Gemini cannot use them for video understanding. Before creating the project folder, VidiStudio uses your configured Gemini connection to confirm that the URL is usable. The bundled macOS Share extension applies the same validation when it accepts one movie from Finder or a public YouTube video page from Safari and compatible browsers, then creates the project and opens its editor automatically. Enable VidiStudio under System Settings → General → Login Items & Extensions → Sharing if it is not already visible in Share menus. System speech narration works offline once projects exist, but project creation and AI stages require the BYOK key.
3. Choose Analyze Video for the complete AI workflow: transcript, summary, then Audio Description text. To work one stage at a time, choose Generate Transcript, Generate Summary, and Generate Audio Descriptions; once content exists, those labels become Regenerate. Regenerate Video Details & Timeline Pictures refreshes only non-AI preparation. Project Information and Video Information remain at the top of the inspector on every editor section. Project Information shows the complete folder size and location; Video Information reports the local source file or YouTube source and its available quality details. The generation controls below stay specific to the selected section. Project > Analysis and each project's contextual Analysis menu contain the complete and individual workflows.
4. Review transcript and Audio Description segments in view mode, then choose Edit to expose selection checkboxes and pencil controls. While Transcript edit mode is active, choose Add Segment or press Command-Shift-N to insert a new transcript segment at the current video time. Descriptions retains the same Add Segment action for a new Audio Description. Edit one row or select several rows and choose Edit Selected to correct their text and timing together. Project &gt; Segments in the menu bar mirrors Edit/Done, Add Segment, Select All, Deselect All, Edit Selected, Delete Selected, Follow, Undo, and Redo with section-aware availability. Select All, Deselect All, and Delete Selected work in Transcript, Descriptions, and the combined AD Transcript. Deleting selected descriptions also permanently removes their corresponding narration files. The timeline shows labeled Thumbnails, Transcript, and Audio Description tracks with a synchronized playhead and millisecond-precision current/total time. A centered transport row below the thumbnails provides Rewind, a single Play/Pause toggle, Stop, and Fast Forward for local and YouTube videos. Pause keeps the current position; Stop pauses video and narration and returns to the beginning. The seek buttons move five seconds. Click or drag the thumbnail strip to seek. Save rejects empty text, invalid ranges, and overlaps between transcript and description segments.
   Transcript, Summary, and Descriptions each expose a right-aligned Generate action, or an explicit Regenerate action when that result already exists. Regenerating Audio Descriptions also removes narration audio associated with the old description segments before generating the new descriptions.
   In Descriptions and AD Transcript, Read Frame Text pauses on the selected playhead position, shows its AI processing status, and uses the final valid frame when the playhead is at the exact end of the video.
5. Synthesize narration. Gemini 3.8 Flash TTS and Flash-Lite TTS speak description text verbatim; the app accepts their WAV output directly. Text that exceeds its time slot must be shortened or retimed. The narration alert identifies the affected description and its spoken duration; use Rewrite to Fit or edit that description before retrying.
6. Open the Export dialog from the inspector, a project's right-click menu, File → Export, or Command-Shift-E while its editor is active. After Save, the All Projects window or Project Editor where the export began shows the same status banner with a spinner, project name, live status, and Cancel Export button until the work finishes or stops. Video exports preserve the original picture when adding audio or closed captions; open captions require a new render and show a quality warning. Web Playback creates a Video.js-ready HLS folder whose highest H.264 rendition preserves the source resolution, then adds every smaller standard tier from 4K through 1080p, 720p, and 480p without upscaling. It also includes AAC audio, selectable Audio Description and WebVTT captions when chosen, a master playlist, and an example player; HDR sources retain their resolution but are tone-mapped to SDR for broad browser compatibility. In Created Exports, each item has one eye-in-a-circle button for opening, revealing, or deleting the complete export. Audio exports include original video audio, the final described mix, and narration-only audio. Changed or missing narration blocks described export.

User-facing errors and warnings use plain language, explain what remains safe, and give a next step. Internal engine, media-tool, operating-system, and service details are written only to private diagnostic logs and are never placed in alerts or inline error messages.

Choose Content to Delete explains every generated component before removal. Selecting AD Descriptions automatically includes Narration Audio and disables that dependent choice because removing all description segments also removes their synthesized narration; deselect AD Descriptions to manage narration independently.

Gemini analysis sends a processing copy through the Files API, polls for ACTIVE with a deadline, saves results locally, and deletes the temporary remote file in a finally block. API keys never enter project folders or process command lines; the engine receives the key through the `VIDISTUDIO_API_KEY` environment variable. General settings are saved to `~/Library/Application Support/VidiStudio/config.json` with owner-only permissions, while the Gemini API key is stored in the macOS Keychain (service `com.vidistudio.gemini-api`). Because it lives in the Keychain rather than the app bundle or config file, it survives app updates and reinstalls and is never written to disk in plaintext.

## Project format

Each portable folder uses `project.json` as the single source of truth for metadata, transcript text, summary, Audio Description segments, undo/redo states, and referenced paths. Local projects keep the imported video in `source/`; `metadata/probe.json` supplies technical video information; `thumbnails/` holds only images referenced by the project; `audio-description/` holds only current synthesized narration; and `exports/` holds only current listed exports. Empty generated folders are removed and recreated when needed. YouTube projects do not create a local `source/` folder. Their YouTube Audio with Narration export temporarily downloads the original audio with bundled yt-dlp and Deno, checks its duration, mixes all current narration, and removes the download on success, failure, or cancellation. Use this for videos you own or have permission to use. Choose MP3 in Format and upload the complete file manually through YouTube Studio → Languages → Descriptive audio; YouTube requires Advanced features and a matching original/dubbed language track. Failed audio downloads automatically retry up to two more times, with a short wait and visible attempt count; cancellation and the overall 15-minute download limit still apply. Retrieval can be blocked by YouTube; importing the matching original video as a local project remains the fallback. YouTube Audio Only exports the downloaded soundtrack without narration, even before analysis. The Audio choices are ordered YouTube Audio Only, Narration Audio Only, and YouTube Audio with Narration. Every audio choice offers WAV (default), MP3, and M4A in a separate Format picker. Local video exports offer MKV (default), MP4, MOV, and M4V; closed-caption MKV exports use SubRip tracks, and MOV retains the native Apple accessibility finalizer. Each unavailable export radio option is disabled individually. Described-video, described-audio, and narration-only choices require current nonempty narration files for every AD segment; transcript/caption choices require their actual text content. Save uses the same checks, and the app rechecks saved narration before invoking the engine. The selected format controls encoding, filename, and replacement matching; choosing another format keeps existing exports. No browser cookies, YouTube sign-in, or downloaded video are used. Paths are relative and confined to the project folder, and saves replace JSON atomically. OS-level locks prevent concurrent engine writes and release on process exit.

Processing audio chunks, speech input, captured OCR frames, duplicate transcript/summary/cue JSON files, unreferenced narration or exports, operation snapshots, and internal export trash are automatically removed. `cleanup-project --project /path/project` migrates and cleans an older project folder while preserving its source or YouTube link and all currently referenced content.

Open Project Folder (Command-Shift-O) opens a project in another location without copying it. New projects default to `~/Documents/VidiStudio Projects`; choose another folder from Settings → Storage → Browse.

## Portable engine

```sh
python3 -m venv .venv
.venv/bin/pip install -r engine/requirements.txt
.venv/bin/python engine/vidistudio_engine.py import-video --video /path/video.mp4 --library /path/projects
.venv/bin/python engine/vidistudio_engine.py transcribe --project /path/project
```

Additional commands: `import-youtube`, `prepare-video`, `validate-config`, `analyze`, `cleanup-project`, `capture-frame`, `rewrite-cue`, `export-subtitles`, `export-audio`, `rename-project`, `undo-cues`, `redo-cues`, `update-metadata`, `attach-video`, and `delete-export`. Use `--help` for arguments.

Core commands: `doctor`, `import-video`, `probe-video`, `generate-thumbnails`, `transcribe`, `generate-summary`, `generate-ad-cues`, `save-cues`, `save-segments`, `synthesize-tts`, `export-open-audio-description-video`, `export-closed-audio-description-video`, `export-closed-caption-video`, `export-open-caption-video`, `export-original-audio`, and `export-described-audio`. `save-segments` atomically validates and replaces the editable transcript and Audio Description rows. Described-video commands accept `--captions none|closed|open` with `--content transcript|combined`; the app presents `combined` as AD Transcript. The older `export-final-video` and `export-selectable-video` names remain accepted for command-line compatibility. Progress and errors are JSON lines on stdout; failure exit code is 1. Set `VIDISTUDIO_CONFIG` to choose an alternate settings file.

Windows uses Python 3.11+ and FFmpeg/FFprobe on PATH (or configured paths), `%APPDATA%/VidiStudio/config.json`, and PowerShell System.Speech for offline voices. Build Windows executables with PyInstaller on Windows; macOS binaries cannot run there. The macOS UI is deliberately separate from the portable engine.

## Validation

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Tests cover path confinement, malformed/overlapping/dialogue-conflicting cues, and an actual generated video import → thumbnails → extraction → system speech → MP4 export pipeline, plus stale narration and missing-key errors. System speech requires access to the OS speech service; restricted execution environments may produce an empty file.

## Runtime and distribution

This direct-distribution app intentionally runs outside App Sandbox to launch its bundled processing tools and access local project folders. Hardened runtime remains enabled for distribution builds. FFmpeg's bundled Homebrew build includes GPL components; redistribution must comply with the included licenses and corresponding-source obligations. No public release is performed by the build scripts.

Settings → About shows the VidiStudio version and opens the bundled FFmpeg GPL license and third-party license files. The App menu's About VidiStudio command opens this section. See [FFmpeg distribution review](docs/ffmpeg-distribution.md) before any public release.

API references: https://ai.google.dev/api/files and https://ai.google.dev/gemini-api/docs/generate-content/speech-generation . Website interaction reference: https://accessivideo.pages.dev/ .

AD segment undo and redo states are bounded and stored in `project.json`; the app no longer creates a second, unbounded folder of whole-project snapshots. Windows engine packaging is provided by `script/build_engine_windows.ps1` and must run on Windows. It does not download or silently install media binaries.

Settings exposes model IDs for every stage, API version, processing mode, prompt pairs, voices, and light/dark/system appearance. Initial values come from `engine/ai-defaults.json`; saved user choices override them without removing newly added default stages or fields. Dedicated speech transcription uses extracted audio with automatic multilingual detection and code-switching; YouTube uses its own configurable video-understanding model. The shared Multilingual Media prompt augments transcript, summary, Audio Description, and screen-text understanding for local and YouTube sources without replacing their existing task prompts.

Current delivery evidence and known feature/validation limits are recorded in `PROGRESS.md` and `FEATURE_PARITY.md`.

## AD views and narration settings

The Editor section opens to Transcript by default and is ordered Transcript (Command+1), Summary (Command+2), Descriptions (Command+3), AD Overview (Command+4), and AD Transcript (Command+5). Descriptions lists authored AD segments; AD Overview reports segment counts, ready/stale/missing audio, and description time, with actions to generate all or missing/changed narration; AD Transcript combines dialogue and AD segments chronologically.

Settings now has a native sidebar: Appearance, Narration, Gemini API, Developer prompts, Storage, Help. Narration offers Apple on-device voices, Piper on-device neural voices, or Gemini TTS for saved audio generation. The Apple voice picker's language/region filter and search list all voices exposed by macOS speech, including installed enhanced voices; each has a Speak Sample action. Download more Apple voices through macOS Accessibility → Read & Speak, then Refresh Voices. Piper offers a catalog of 178 downloadable neural voices with language and quality filters, four sort orders, plain-English language and dialect labels, hosted sample previews, per-row download progress, checksum verification, a Delete Voices list with the same filters, sorting, and samples, and removal progress; downloaded voices work offline for samples, saved narration, live preview, and summary read-aloud. Save Settings preserves the chosen voice and engine. The same Piper catalog and controls are available on Windows.

For playback, choose generated audio or on-device speech without audio files, then enable Narration in the editor. On-device speech restarts the active cue after seeking/resuming and stops at its end; use generated audio for precise timing and final exports. No additional local LLM is required. Gemini premium generation still requires a configured personal API key.

### Voice samples in Settings

Settings → Narration shows samples for the selected speech engine. Apple voices offer Play Selected Voice (including the system default), individual Speak Sample buttons, and Stop Sample. Gemini offers the online voice list plus a custom voice ID, editable sample text, Play Voice Sample, Stop Sample, and Cancel Generation. Gemini previews use current unsaved settings through an owner-only temporary config; they do not change projects or save settings. Samples are cached within the Settings session and removed when leaving the Gemini section. Changing voice or sample stops playback. A Gemini API key is required; requests use the configured TTS model and prompt.

Summary read-aloud uses the Apple or Piper voice and speech controls chosen for narration. It reads the summary in the Summary view and from Playback → Summary Reading, keeps the sentence highlighted exactly, and estimates the spoken word from playback progress. It never creates files in the project. Live preview playback (**Preview segment text with the selected voice**) also uses the selected local Apple or Piper voice and never sends text online. Azure Voices and the Windows natural-voice bridge were removed from both desktop apps; settings saved with those legacy engines migrate to Apple Voices on Mac and to Windows OneCore or SAPI 5 on Windows.

### Preview workspace

Use **View → Hide Preview** or Command+Shift+V to collapse the video and timeline while keeping the player loaded. The same command changes to **Show Preview**, so the preview can always be restored from the View menu or keyboard. **View → Hide Timeline** collapses the complete timeline section, including thumbnails, transport controls, Transcript segments, and Audio Description segments, and changes to **Show Timeline** for restoration. The transport buttons use the same shortcuts as Project → Playback: Command+Shift+Space for Play/Pause, Command+Shift+Period for Stop Video, Command+Option+Left Arrow to rewind five seconds, and Command+Option+Right Arrow to move forward five seconds. The preference persists across project windows and launches. Project editor opening, preview, timeline, inspector, Settings and Export presentation, and Settings disclosure changes use short native-feeling transitions; macOS Reduce Motion disables this added movement. Close an editor with its standard red window Close button; All Projects remains available in its own window. Full-Screen Video (Command+Option+F) presents the video separately from the editor; Escape restores it. Full-Screen Video remains in **Project → Playback** and both shortcuts are included in the keyboard reference.

### Fixed project list and inspector

The project list (252 points) and inspector (272 points) have fixed widths and no resize handles. Their toolbar buttons show or hide them independently; the center editor takes the remaining width. Long project names wrap. In All Projects, VoiceOver identifies the three source-filter buttons as All Projects, Local Video Projects, and YouTube Projects rather than reading their icon names. Right-click a project in List or Grid View for an Analysis menu containing non-AI metadata/thumbnail preparation, Analyze Video, and each individual AI stage. The contextual menu also includes project-specific Export, Open in Project Folder, Rename, and Delete. Local projects expose Video, Audio, Text, and Web Playback choices in the export dialog; YouTube projects omit Video and Web Playback while retaining Audio and Text exports, including a complete described audio file for YouTube Studio when every description has current narration. The labeled timeline beneath the preview displays optional thumbnail frames followed by spoken Transcript segments and Audio Description segments.

Targeted Audio Description refinement is available in the enlarged Add/Edit segment dialog. Manual Description text and the optional Hint for Gemini use separate text boxes: Save Segment stores the manual description, while Re-Analyze This Segment uses the hint with the selected video range and project context, reconciles nearby descriptions, validates timing, and supports Undo. The inspector shows Gemini-checked video availability and a human-readable retention countdown with consistent numeric values for days, hours, minutes, and seconds; the full window is 2 days, and valid uploads are reused.


Targeted Transcript generation is available in the same enlarged Add/Edit Segment dialog. Choose a time range, optionally enter a separate Hint for Gemini, and select Re-Analyze This Segment (Command-Option-R). Gemini can generate multiple segments and reconcile immediate transcript neighbors; unrelated transcript rows remain unchanged. The shared multilingual system and user prompts accompany the local or YouTube transcript prompt, preserving every spoken language, code-switching, and original scripts. Range analysis uses the configured Transcript video model, or the configured YouTube Transcript video model when Transcript uses an audio-only transcription model. It does not require a pre-existing transcript or summary. Manual text still uses Save Segment.

Existing AD segments, narration files, and the summary are preserved during transcript range generation. Accurate speech that conflicts with existing AD timing causes the proposal to be rejected without saving; review and adjust the conflicting description before retrying. Empty, malformed, out-of-range, or overlapping transcript proposals never replace existing content. Transcript Undo/Redo restores saved transcript edits on Transcript; description history remains separate on Descriptions. Deleting transcript rows clears transcript history so permanently deleted rows cannot be restored. History restoration also checks current AD/dialogue timing. Successful segment edits invalidate the current export listing, as other segment edits do; create fresh exports afterward. The Regenerate Transcript warning explains that full regeneration replaces manual transcript edits and clears transcript history, preserves other content, and offers range generation as the targeted alternative. Review retained AD timing after full regeneration.

Active exports appear across All Projects, project editors, and Settings with a spinning activity indicator, progress bar, percentage when available, current step, and a session-specific Cancel Export button. Video and audio progress follows FFmpeg media time; Web Playback combines all renditions and audio tracks. Unknown download sizes show indeterminate progress, and the banner stays active through validation and native metadata finalization.

Video soundtrack tracks use AAC in MKV, MOV, MP4, and M4V. Existing AAC audio is kept; other source audio is converted. Original and described audio have explicit names, language metadata, and default/accessibility flags. Descriptive subtitles use the Matroska text-description flag or MP4 description role; all MOV export modes receive native Apple audio/caption characteristics. HLS captions use spoken-dialog characteristics without falsely claiming sound-effect captions, and descriptive transcripts are manually selectable. Track language metadata currently uses English; other-language auto-tagging is not implemented. `script/audit_export_tracks.py` retains a complete export matrix and a JSON report, checking AAC, track identities, subtitle text/timing, media decoding, and AVFoundation selection on Apple-supported containers.
