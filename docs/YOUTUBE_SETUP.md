# Desktop Google sign-in and YouTube Data API

The Mac and Windows apps reuse their existing Vertex AI desktop OAuth clients for Google sign-in. Keep each Google-issued client configuration in the gitignored `Config/vertex-desktop.json` for its platform. Both authorization requests use loopback and PKCE. Settings > AI requests Google Cloud access. Settings > YouTube Accounts requests YouTube access for browsing and caption import. Each stores its own credential in the operating system vault. Keep the YouTube Data API v3 enabled in the OAuth project. Add the Cloud Platform and YouTube force-ssl scopes to the Google Auth Platform configuration and complete the applicable Google verification before public distribution.

After the Google redirect, both desktop apps display a VidiStudio page in the browser. **Return to VidiStudio** means the browser step is complete. The app finishes connecting and shows the saved account. If the user cancels or Google denies access, **Sign-in didn’t finish** tells the user to retry from the app.

Keep the publisher-provided YouTube Data API v3 key in `Config/youtube-release.json` under `apiKey`. Packaging generates the per-app resource from this key and the Vertex desktop client configuration. The public and unlisted video link path always uses the Data API key. Keep the key restricted to the YouTube Data API and check its quota.

Verify Add Account in YouTube Accounts and Google sign-in in AI Settings independently. Check that each consent prompt requests its service, switch between two YouTube accounts, and confirm Cloud project access still uses the account connected in AI. Fetch a public and an unlisted video by link. For private-video opening and analysis, test the same owner signed in to both services, two different accounts, either connection alone, and an API key alone. Import captions from a video the YouTube account can edit. Disconnect each service on a test device and verify the other can still access its service. Existing combined connections can reconnect separately to refresh each grant. In-app disconnection removes local access. Google account-wide revocation removes all grants for the OAuth project, even when the project has multiple clients.

See [Google’s desktop OAuth documentation](https://developers.google.com/identity/protocols/oauth2/native-app) and the [YouTube caption download requirements](https://developers.google.com/youtube/data/reference/rest/v3/captions/download).
